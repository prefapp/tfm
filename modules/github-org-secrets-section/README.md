# **GitHub Organization Secrets Terraform Module**

## Overview

This module manages GitHub **organization-level** secrets for **Actions**, **Codespaces**, and **Dependabot** using a single strongly-typed `config` object. It is compatible with GitHub Automated Provisioning Systems such as `ghaps` because all desired state is supplied through one top-level `config` input.

The module applies to the GitHub organization configured in the GitHub provider; `config.org` is validated and returned as an output and should match the provider organization.

**Important**:
The `value` field in each secret entry **must already be encrypted** using **libsodium** with the target organization's matching secret type public key.
**Terraform does not perform any encryption**. It forwards these pre-encrypted ciphertext values to the GitHub API. Actions and Dependabot secrets are sent through the provider's `value_encrypted` argument with the matching public-key ID; Codespaces secrets use the provider's `encrypted_value` argument.

**Provider limitation**: The GitHub Terraform provider's `github_codespaces_organization_secret` resource does not support a `key_id` argument. The module fetches the codespaces organization public key for consistency (all three secret types retrieve their public key), but the `key_id` is not passed to the codespaces resource. This is a provider-side limitation; the `key_id` argument is only available on `github_actions_organization_secret` and `github_dependabot_organization_secret`.

This approach is the most secure for automated pipelines (Prefapp IDP, GitHub Actions, etc.).

## Key Features

- **Single complex object**: All secrets are defined in one `config` variable with per-secret visibility control.
- **Pre-encrypted values**: Map values for each secret must be provided as libsodium-encrypted ciphertext strings.
- **Three secret types**: Actions, Codespaces, and Dependabot supported in the same module.
- **Per-secret visibility**: Each secret can independently be scoped to `all`, `private`, or `selected` repositories.
- **Selected repository binding**: Actions and Dependabot use separate `_repositories` binding resources; Codespaces uses inline `selected_repository_ids`.
- **Deterministic secret updates**: When optional `*_sha256` maps are provided, the module uses `terraform_data` + `replace_triggered_by` to detect actual plaintext changes. The non-deterministic ciphertext diff is suppressed via `ignore_changes`.
- **Repository resolution**: Selected repositories are accepted as `owner/repo` strings and resolved to integer IDs via data sources.
- **JSON-native**: Works seamlessly with `terraform.tfvars.json` generated by external programs.

## GitHub Automated Provisioning Systems Compatibility

Expected `terraform.tfvars.json` shape:

```json
{
  "config": {
    "org": "my-org",
    "actions": {
      "MY_API_KEY": {
        "value": "<libsodium-encrypted-actions-value>",
        "visibility": "all"
      }
    },
    "actions_sha256": {
      "MY_API_KEY": "<64-char-lowercase-hex-sha256>"
    },
    "codespaces": {},
    "dependabot": {}
  }
}
```

The module maps to one Firestartr custom resource, one GitHub organization secret section, and one Terraform state. Secret map keys are GitHub secret names. Secret map `value` fields are encrypted ciphertext strings; do not pass plaintext secrets.

When `*_sha256` maps are provided alongside the secret groups, the module uses `terraform_data` resources whose `input` is the SHA-256 digest. If the plaintext value changes, the digest changes, the `terraform_data` input changes, and `replace_triggered_by` triggers a replacement of the secret resource. The `ignore_changes` lifecycle rule continues to suppress spurious diffs from the non-deterministic libsodium ciphertext.

When `*_sha256` maps are absent, `terraform_data` resources have a stable `null` input, so no replacement is ever triggered. The secret lifecycle remains unchanged from the pre-fix behavior. To enable automatic updates, provide the SHA-256 digests.

## Basic Usage

### Using `terraform.tfvars.json` (recommended)

```hcl
module "org_secrets" {
  source = "git::https://github.com/prefapp/tfm.git//modules/github-org-secrets-section"

  config = var.config   # Terraform automatically loads terraform.tfvars.json
}
```

### Inline example

Manages GitHub secrets for **one organization**.

```hcl
module "org_secrets" {
  source = "git::https://github.com/prefapp/tfm.git//modules/github-org-secrets-section"

  config = {
    org = "my-org"

    actions = {
      "MY_API_KEY" = {
        value      = "r+RFBGIn8U7z2Opm5RN7PXKdgFzefXiV91IpG3O2DrClZl9dkTJBfhRZbi2uV2nu..."
        visibility = "all"
      }
    }
    codespaces = {}
    dependabot = {}
  }
}
```

## Import Behavior

Existing secrets can be adopted into Terraform state, but GitHub does not return secret values during import. Keep non-empty ciphertext placeholders in `config`. Without a matching `*_sha256` entry the trigger input stays `null` (stable), so the imported secret drifts from the placeholder but is never replaced.

Import addresses and IDs:

- Actions: `github_actions_organization_secret.this["SECRET_NAME"]` with ID `SECRET_NAME`.
- Codespaces: `github_codespaces_organization_secret.this["SECRET_NAME"]` with ID `SECRET_NAME`.
- Dependabot: `github_dependabot_organization_secret.this["SECRET_NAME"]` with ID `SECRET_NAME`.
- Actions repos binding: `github_actions_organization_secret_repositories.this["SECRET_NAME"]` with ID `SECRET_NAME`.
- Dependabot repos binding: `github_dependabot_organization_secret_repositories.this["SECRET_NAME"]` with ID `SECRET_NAME`.

## Delete Behavior

`terraform destroy` deletes the managed GitHub organization secrets from Actions, Codespaces, and Dependabot, and removes the selected repository bindings. This affects only the secret entries represented by `config`; deleting an imported secret permanently removes that GitHub secret value unless another system recreates it.

Deleting a secret also deletes its associated repository bindings (if any). The selected repository access is revoked when the binding resource is destroyed.
