# Guard Managed Resource Deletion

OVHcloud's native `deletion_protection` protects only the managed PostgreSQL cluster. The module also owns databases, PostgreSQL users, PgBouncer pools and OKMS secrets, whose deletion can otherwise proceed before OVHcloud rejects cluster deletion. A `terraform_data` destroy-time guard follows each managed child's ID or secret path and stores the applied protection setting. A separate guard follows both the OKMS ID and path for every secret, so changing the KMS cannot replace a secret without checking the same applied protection setting. Keeping these identities separate preserves existing path-guard state without forcing replacement during rollout. A second barrier depends on every child and OKMS guard, so during a complete destroy it runs first and prevents the independent guards from running in parallel if protection is enabled.

The trade-off is reliance on Terraform's local shell provisioner and a multi-step intentional deletion: set `deletion_protection = false`, apply, then destroy or remove the child configuration. The module configuration must remain present while Terraform destroys these resources; removing the module block also removes its destroy-time provisioners. The OVHcloud cluster retains its native deletion protection.
